# C32/K8 raw-command core slice

Status: tracked simulation-only vertical slice. One unchanged K16-format raw
command BO is executed through the C32/K8 core. K16 remains the default and
reference profile. No profile decode, DMA/body/tail, AXI endpoint, backend
packing, real-capture replay, FPGA, board or bitstream change is included.

## Implemented chain

- `rtl/cmac/rk_cmac_array_front.sv` is `ATOMIC_C`/`ATOMIC_K` parameterized:
  it reads `ATOMIC_K*32` weight halfwords per operand frame, steps OC by
  `ATOMIC_K`, closes at `oc == ao-ATOMIC_K`, and advances the weight group by
  `ATOMIC_K*32*2` bytes. The output atom base advances 16 bytes for the first
  OC8 half, 48 bytes for the second, and the next OC16 block stays at the
  64-byte stride with the 16-halfword gap.
- `rtl/cmac/rk_cmac_frame_output.sv` is `ATOMIC_K` parameterized: it captures
  `ATOMIC_K*32` bits, walks `ATOMIC_K` lanes, writes at `address+lane*2`, and
  asserts `in_last` on lane `ATOMIC_K-1`.
- `rtl/cmac/rk_cmac_array_datapath.sv` is `ATOMIC_C`/`ATOMIC_K`
  parameterized and instantiates the CACC array and frame writer with the
  same K.
- `rtl/cmac/rk_cmac_array_core.sv` propagates `ATOMIC_C`/`ATOMIC_K` to the
  front and datapath.
- `rtl/rk_cmac_profile.sv` is unchanged. The host still writes
  `0x10014024=16`; the K8 front interprets the logical OC16 job and splits it
  internally.

K16 defaults are unchanged: `ATOMIC_C=32`, `ATOMIC_K=16`. The seven tracked
K16 source manifests (`rtl/ddr/*/sources.json`) were rebound only for the four
changed HDL file hashes; every manifest still declares `atomic_c=32` and
`atomic_k=16`.

## Raw-command case

Source case: `m2_n17_k65_finite` from
`build/rknpu-array-core-vectors` (the finite variant of the unchanged
`build/cmac_vectors/m2_n17_k65` compiler command capture).

| Field | Value |
|---|---|
| Command QWORDs | 49 (45 body + 4 tail) |
| Host `0x10014024` | `16` (logical OC16) |
| Commands SHA-256 | `457f2d8af9afdba667ad5de6bc24420d94870ab88cda1715df225ac766b0818b` |
| Logical shape | rows=2, ai=96, ao=32 |
| K8 operand frames | 24 (row -> physical OC8 -> IC32) |
| K8 memory reads | 6912 (32 input + 256 weight per operand frame) |
| K8 output frames | 8, 8 halfwords each |
| K8 output writes | 64, all finite and distinct |
| K8 weight layout | `(N/8, K/32, 8, 32)` |

This finite case is used deliberately: all 64 expected output halfwords are
finite (no NaN/Inf) and distinct, so the exact compare exercises numerical
values rather than only exception encodings.

The K8 case is generated by `tools/cmac/gen_array_core_vectors_k8.py`:

- commands and input are byte-identical to the K16 case;
- weights are repacked from `(N/16, K/32, 16, 32)` to
  `(N/8, K/32, 8, 32)`;
- `reads.hex` is regenerated for the K8 front traversal;
- `writes.hex` is the unchanged K16 write list re-chunked into two
  eight-halfword OC8 frames per OC16 block. The first OC8 frame is at
  `block base + 0`, the second at `block base + 16` bytes, and the
  16-halfword gap is retained.

The numerical values are therefore exactly the K16 reference values for the
same kernels; the K8 split changes the frame schedule, not the arithmetic.

## Results

Command:

```sh
python3 tools/cmac/gen_array_core_vectors_k8.py
python3 tools/cmac/test_array_core_k8.py --tool iverilog --suite protocol
python3 tools/cmac/test_array_core_k8.py --tool verilator --suite protocol
```

| Tool | Mode 0 | Mode 2 (failed final write) |
|---|---|---|
| Icarus Verilog 13.0 | `reads=6912 writes=64 acknowledgments=64 jobs=1` | `reads=6912 writes=64 acknowledgments=63 jobs=0` |
| Verilator 5.048 | `reads=6912 writes=64 acknowledgments=64 jobs=1` | `reads=6912 writes=64 acknowledgments=63 jobs=0` |

The K8 bench compares every read address/data pair and every write
address/data pair, then checks the complete output memory: written halfwords
must match the K16-derived values and every gap halfword must remain the
sentinel. Mode 2 proves a failed final K8 write cannot report frame/job
completion.

K16 regression:

| Test | Result |
|---|---|
| `test_array_core.py --suite smoke` | PASS, one K16 case plus modes 1/2/3/4/5/7/9 |
| `test_array_core.py --suite full` | PASS, 16 tests: eight K16 shape cases plus modes 1/2/3/4/5/7/9 and reset/mode 6; 2,893.8 s, no failures |
| K16 front manual replay, Icarus | 13 good runs, 14 fault runs, 5 reset phases, 3 cancels, 3 profile faults, 109 checked frames |
| K16 front manual replay, Verilator | 13 good runs, 10 fault runs, 5 reset phases, 3 cancels, 3 profile faults, 109 checked frames |
| `test_array_datapath.py --suite smoke` | PASS |
| `test_array_dma.py --suite smoke` | PASS |
| `test_cmac_cacc.py --kernels 16 --array legacy` | 208 frames, 400 outputs, 10 resets, 3 cancels |

The K16 front replay used the existing K16 command/operand and front-frame
fixtures directly; its old report binding is stale relative to the current
`build/cmac_vectors/vectors_report.json` in the source workspace, so the
report-verifying wrapper was not used. The K16 core full suite independently
covers the same front path.

## Remaining blockers

- K8 profile decode/readback semantics for the logical host field.
- DMA amount/tail audit for the K8 frame format.
- AXI endpoint parameter plumbing.
- Backend `(N/8, K/32, 8, 32)` packing and OC8 output-atom schedule.
- Real conv-simple/conv-fp16/conv-gemm/GEMM capture replay.
- Full-top synthesis, placement, route, timing, DRC, bitstream and hardware.

This slice is **not** ready for full-top synthesis. It is ready for the next
isolated profile/DMA increment at the core boundary.
